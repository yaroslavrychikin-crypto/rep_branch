##  Уровень 1: Базовые Issues

**Задача 1.1 — Создание Issue**
Создай Issue в своём тестовом репозитории с заголовком «Кнопка "Отправить" не реагирует на клик». В описании укажи:
- Шаги воспроизведения (3 шага)
- Ожидаемое поведение
- Фактическое поведение
- Окружение (браузер, ОС)

**Задача 1.2 — Работа с метками и исполнителями**
К созданному Issue:
- Добавь метки `bug` и `high priority`
- Назначь себя исполнителем (Assignee)
- Добавь комментарий с предположительной причиной ошибки
- Привяжи Issue к Milestone «Sprint 1»


**Задача 1.3 — Поиск и фильтрация**
Создай 5–6 Issue с разными метками. Найди через поиск:
- Все открытые Issue с меткой `bug`
- Issue, назначенные на конкретного пользователя
- Issue, созданные за последнюю неделю

##  Уровень 2: Pull Request — базовый цикл

**Задача 2.1 — Первый PR**
1. Создай ветку `fix/button-click` от `main`
2. Внеси любое изменение (например, исправь опечатку в README)
3. Запушь ветку и открой Pull Request в `main`
4. В описании PR напиши `Closes #1` (где 1 — номер твоего Issue)
5. Проверь, что Issue автоматически закрылся после мерджа

**Задача 2.2 — Ревью и правки**
1. Открой PR с изменением кода
2. Попроси коллегу (или второй аккаунт) оставить комментарий к конкретной строке в **Files changed**
3. Внеси правку по комментарию и запушь в ту же ветку
4. Убедись, что новый коммит появился в PR автоматически

**Задача 2.3 — Draft PR**
1. Создай PR как **Draft** (черновик)
2. Убедись, что кнопка Merge неактивна и ревьюеры не запрашиваются
3. Добавь ещё пару коммитов
4. Переведи PR в статус **Ready for review**

**Задача 2.4 — Конфликты**
1. Создай ветку `feature/a`, измени строку 1 в файле `test.txt`
2. Создай ветку `feature/b` от `main`, измени ту же строку 1 иначе
3. Открой PR из `feature/a` и смерджи
4. Открой PR из `feature/b` — получи конфликт
5. Разреши конфликт локально, запушь и заверши мердж
